# UI-006：建立最终 BurnCloud UI Quality / Golden Page Gate

## 第一层：人类阅读区（Human Readable Layer）

**状态：PLANNED**  
**类别：Release Gate**  
**功能依赖：Release 页面完成、UI-004（适用）、UI-005**

### TL;DR

页面“看起来完成”不等于 BurnCloud UI 迁移完成。最终必须同时证明数据正确、Auth/Tenant 安全、状态完整、没有 mock/第二前端、可访问性通过、Golden Page 不漂移、旧 deep link 兼容。

### 范围速览（In / Out）

| ✅ 做 | ❌ 不做 |
| --- | --- |
| build/runtime/security/state gates | 不在 Gate Issue 里补未完成页面 |
| Golden Page visual QA | 不用截图覆盖功能错误 |
| accessibility/deep-link regression | 不关闭失败测试 |
| no-mock/no-second-frontend checks | 不 bless unrelated drift |

### 审批者关注点（Reviewer Focus）
1. correctness 是否高于 visual beauty？
2. auth/data/state failure 是否能阻断发布？
3. Golden Page 是否只校准视觉，而不是成为业务事实源？

---

## 第二层：机器执行层（Machine Executable Specification）

### 1. Goal

建立一个可重复的 Release Acceptance Gate，为 BurnCloud UI 迁移输出明确 pass/fail 证据。

### 2. Evidence

- STATIC CONFIRMED — current repo 已有 UI convention/functional/product/visual check scripts 与 client UI workflow。
- STATIC CONFIRMED — engineering docs 要求 Cargo/Dioxus、Web/Desktop/LiveView（适用）、1440×900 + narrower desktop 验证。
- STATIC CONFIRMED — Target Design System 指定 Golden Pages 校准视觉，截图不是 source of truth。
- UNKNOWN — final Golden Page set 与自动 visual comparison mechanism 要在目标页面批准后确定。

### 3. Entry / Starting Point

```text
crates/client/scripts/check-*.sh
.github/workflows/client-ui.yml
docs/ui/*
approved Golden Pages
all required UI plan implementations
```

### 4. Reuse Targets / Do Not Recreate

Reuse：existing gates/Rust tests/Dioxus launch paths/security tests。  
Do Not Recreate：与 production 脱节的第二测试体系、mock truth acceptance。

### 5. Scope

Allowed：final checks/workflows/E2E/visual QA/acceptance docs。  
Avoid：补页面/backend、architecture refactor、弱化 security tests。

### 6. Behavior Contract

**Inputs**：merged production UI + approved contracts/Golden Pages + executable fixtures。  
**Outputs**：明确 pass/fail + failure location/evidence。  
**Ownership**：CI verifies；source/backend remain truth。  
**Side Effects**：test/check definitions only。

### 7. Failure / Forbidden Fallbacks

任何 required gate failure 都阻断完成。Visual pass 不覆盖 auth/data failure；functional pass 不覆盖严重 accessibility/approved visual regression。禁止 disable test、mock pass、snapshot bless unrelated drift。

### 8. Impact / Invariants

CI/quality process only。保持 correctness > visual beauty；one Dioxus frontend；tests verify accepted truth, do not define truth。

### 9. Dependencies

UI-001/002/003、release target pages、UI-004 where applicable、UI-005、approved Golden Pages。

### 10. Stop Conditions

```text
STOP IF:
- acceptance requires ignoring auth/tenant/data/state failure
- Golden Page source is not approved
- tests depend on production mock truth
- route compatibility is incomplete
- required runtime mode cannot be meaningfully tested
```

- [ ] final diff 无 unrelated semantic/architecture drift。
