# UI-006：建立最终 UI Quality / Golden Page Gate

## 第一层：人类阅读区（Human Readable Layer）

**状态：PLANNED**  
**类别：Release Gate**  
**功能依赖：Release 页面 + UI-004、UI-005、UI-007、UI-008**

### TL;DR

最终验收必须同时证明：真实数据、权限/tenant 隔离、`/console` namespace、i18n、完整状态、Golden Page、Web/Desktop/LiveView，以及**退役 root route 不再存在且不会落入 data-plane fallback**。

---

## 第二层：机器执行层（Machine Executable Specification）

### 1. Goal

建立可重复的 production UI acceptance gate，阻止“页面完成但 auth、route、账务语义或 fallback 边界错误”的 PR 进入 main。

### 2. Evidence

- current repo 已有 UI convention/wiring/product UX/visual-system checks。
- Dioxus 有 Web/Desktop/LiveView 多运行形态。
- UI-007 定义 i18n。
- UI-008 定义 `/console/*`、temporary compatibility 和 retired root contracts。
- Server 使用 data-plane fallback，因此 retired root outcome 必须被测试。

### 3. Entry / Starting Point

existing client check scripts/workflows、security tests、server route tests、UI-007、UI-008、Golden Pages、release role pages。

### 4. Reuse Targets / Do Not Recreate

Reuse existing checks/Cargo/Dioxus/auth tests。Do Not Recreate 第二测试体系、mock production truth、snapshot-only acceptance。

### 5. Scope

Allowed：final checks/workflows、route/auth/i18n matrix、visual QA、E2E、accessibility、temporary redirect tests、retired-route fallback safety tests。  
Avoid：在本 Issue 里补未完成 backend/page、弱化安全检查。

### 6. Behavior Contract

必须覆盖：

```text
role × canonical route × locale × state
```

Temporary compatibility 代表性：

```text
/billing → /console/buyer/billing
/playground → /console/buyer/playground
```

Retired root 代表性：

```text
/models
/logs
/providers
/routes
/guardrails
/evaluation
/team

→ no redirect
→ no Dioxus page
→ no management API action
→ no data-plane fallback
→ explicit 404/410
```

Billing 权限矩阵：

```text
Buyer + /console/buyer/billing + zh → allowed
Admin + /console/admin/billing + en → allowed
Buyer + /console/admin/billing + zh → forbidden
Admin + /console/buyer/billing + en → only if user also has Buyer authorization
/billing → /console/buyer/billing redirect-only
```

### 7. Failure / Forbidden Fallbacks

任何 auth/data/route/i18n failure 都是 failure。尤其以下任一情况必须 fail：

```text
retired root redirects
retired root renders HTML shell
retired root reaches router_app/data plane
retired root invokes management API
```

Visual pass 不能覆盖 security/financial semantic failure。

### 8. Impact / Invariants

CI/quality only。必须验证 INV-UI-ROUTE-001 / 002 / 003、Backend Authorization final、Buyer/Admin Billing separation。

### 9. Dependencies

UI-007、UI-008、UI-004、UI-005 + required Buyer/Supplier/Admin pages + Golden Pages。

### 10. Stop Conditions

STOP IF retired root 的 404/410 无法在 data-plane fallback 前验证，role/tenant tests 被要求跳过，Buyer/Admin Billing 被混合，或测试需要 production mock。

## 第三层：验收层（Definition of Done）

- [ ] Cargo/Dioxus build 与现有 UI checks 通过。
- [ ] `/console/buyer/*` `/console/supplier/*` `/console/admin/*` canonical deep links 验证。
- [ ] `/console/api/*` `/console/internal/*` 不被 UI catch-all 吞掉。
- [ ] `/models` `/logs` `/providers` `/routes` `/guardrails` `/evaluation` `/team` 均无 redirect/page/alias，并返回 404/410。
- [ ] 七个 retired root 均不会进入 data-plane fallback。
- [ ] temporary compatibility roots 只 redirect，不读取数据/执行管理动作。
- [ ] unauthorized workspace/page 被拒绝。
- [ ] safe `return_to` verified。
- [ ] Buyer Billing / Admin Billing / Revenue / Settlements 语义隔离测试。
- [ ] `en/zh` 关键页面无 overflow；`zh-TW/ja` Shell/关键页面 smoke 通过。
- [ ] machine identifiers 不翻译。
- [ ] locale-aware financial/date/number formatting 验证。
- [ ] Loading/Empty/Partial Failure/Error/Recovered 覆盖。
- [ ] no production mock / duplicate frontend。
- [ ] keyboard/focus/non-color-only accessibility 通过。
- [ ] Golden Page 1440×900 + narrower desktop QA 通过。
- [ ] Web/Desktop/LiveView route semantics 一致。
- [ ] branch + PR。
