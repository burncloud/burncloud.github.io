# UI-003：建立 Production Shell 与 Role/Auth Workspace

## 第一层：人类阅读区（Human Readable Layer）

**状态：PLANNED**  
**类别：Foundation**  
**功能依赖：UI-001、UI-002、UI-007**

> 本页只定义 authenticated Console Shell / Workspace。Canonical URL namespace 由 UI-008 定义；具体页面业务由各页面计划负责。

### TL;DR

把当前以 Providers / Models / Routes 为中心的 Console Shell 改造成 Buyer / Supplier / Admin workspace。Role 只能来自 Backend Authorization；Role Switcher 只能在已授权 workspace 间切换。Console Shell 的最终 URL 统一位于 `/console/*`，但具体 path matrix 由 UI-008 单一维护。

### 背景与动机（Why）

current Dioxus 已有 single Router、AuthGate、Sidebar/Topbar，但 `AuthGate` 当前只判断是否 authenticated，页面 URL 仍是 `/models`、`/billing` 等根级路径。Target Workbench 又允许 URL/前端 state 切 role，这只适合作为原型，不能成为生产权限模型。

### 范围速览（In / Out）

| ✅ 做 | ❌ 不做 |
| --- | --- |
| authenticated `/console` shell | 不让 URL 授权 |
| Buyer/Supplier/Admin workspace | 不让 localStorage 授权 |
| backend roles/capabilities | 不实现具体页面业务 |
| WorkspaceGate presentation | 不替代 backend API authorization |
| Sidebar/Topbar/Search | 不创建第二 Router |
| safe login return_to | 不删除 legacy routes |

### 风险与安全网（Risk）

最高风险是把“导航可见性”或“URL 前缀”误当权限。任何 unknown role 不得 fallback Admin；任何 `/console/admin/*` URL 都不能让未授权用户获得 Admin 数据。

### 审批者关注点（Reviewer Focus）

1. Backend Authorization 是否始终是最终权限真相？
2. `AuthGate → WorkspaceGate → Page` 是否职责清楚？
3. 多角色用户是否只在已授权 workspace 间切换？
4. locale / URL / localStorage 是否都不能提升角色？

## 第二层：机器执行层（Machine Executable Specification）

### 1. Goal

建立生产 Dioxus authenticated Console Shell：

```text
/console/*
    ↓
AuthGate
    ↓
authenticated?
    ↓
WorkspaceGate
    ↓
backend-authorized Buyer/Supplier/Admin?
    ↓
Page
```

UI-003 定义 Role/Auth Workspace 行为；UI-008 定义 canonical URL tree。

### 2. Evidence

- STATIC CONFIRMED — `crates/client/src/app.rs::Route` 是 current Dioxus Route source。
- STATIC CONFIRMED — current protected pages 位于根级 `/`、`/models`、`/billing` 等，并由 `#[layout(AuthGate)]` 包围。
- STATIC CONFIRMED — current `AuthGate` 只检查 `is_authenticated()` 并 redirect Login。
- STATIC CONFIRMED — `AuthContext::CurrentUser` 已包含 backend roles。
- STATIC CONFIRMED — current Server management API 已使用 `/console/api/*`；internal 使用 `/console/internal/*`。
- STATIC CONFIRMED — Target Workbench 的 `RoleContext` 可根据 URL/前端 state 改 role，因此只可作为 Target UX reference，不能复制其 authority model。
- UNKNOWN — implementation-time canonical backend role/capability vocabulary；READY 前必须重新确认。

### 3. Entry / Starting Point

```text
crates/client/src/app.rs
crates/client/src/auth_gate.rs
crates/client/src/functional_layout.rs
crates/client/src/backend.rs :: CurrentUser/AuthContext
backend role/authorization tests
UI-007 localization contract
UI-008 route contract
```

### 4. Reuse Targets / Do Not Recreate

Reuse：existing Dioxus Router、AuthGate/AuthContext、Sidebar/Topbar/Search、Desktop chrome、Web/LiveView runtime。  
Do Not Recreate：second Router、second auth shell、client role DB、client permission engine、React production frontend。

### 5. Scope

Allowed：authenticated Console shell、workspace selection state、AuthGate/WorkspaceGate composition、safe `return_to` plumbing、Sidebar/Topbar/Search workspace behavior、targeted auth/navigation tests。  
Avoid：具体页面业务、backend role mutation、API authorization redesign、legacy route removal、billing/routing semantics。

### 6. Behavior Contract

**Inputs**：authenticated user identity、backend-authorized roles/capabilities、requested/last workspace、requested internal `return_to`。  
**Outputs**：active authorized workspace + corresponding shell/navigation/search scope。  
**Ownership**：Backend grants roles/capabilities；Shell only selects/presents granted workspace。  
**Side Effects**：navigation/workspace preference only。

Workspace preference 可以持久化，但必须：

```text
saved workspace
      ↓
intersect backend-authorized workspaces
      ↓
allowed only
```

### 7. Failure / Forbidden Fallbacks

- 未登录访问 `/console/*` → Login，并保存受验证的内部 `return_to`。
- 登录后原 workspace 未授权 → explicit Forbidden/Unavailable，不偷偷进入 Admin/其他 workspace。
- unknown/no supported role → explicit unavailable state。
- `return_to` 只允许 BurnCloud 内部 Console path，禁止 open redirect。

Forbidden：URL → Role、localStorage → Role、username → Role、隐藏 Sidebar → Authorization、unknown → Admin。

### 8. Impact / Invariants

```text
persistence: optional workspace preference only
external_calls: auth/current-user only
auth_authorization: consumed from backend, never defined by UI
frontend_navigation: yes
```

必须保持：one Dioxus Router；backend authorization final truth；workspace switch 不授予权限；locale 不改变 role/path authority。

### 9. Dependencies

UI-001、UI-002、UI-007。Canonical routes 由后续 UI-008 锁定。实现前重新确认 backend role/capability vocabulary 与 authorization tests。

### 10. Stop Conditions

```text
STOP IF:
- backend lacks stable role/capability facts
- Shell must invent permission rules
- URL/localStorage must grant workspace to proceed
- implementation requires deleting legacy routes
- second Router/frontend is proposed
- safe return_to cannot be guaranteed
- Desktop/Web/LiveView compatibility cannot be preserved
```
