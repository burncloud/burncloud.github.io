# UI-008：建立 Console Namespace 与 Route Authorization Contract

## 第一层：人类阅读区（Human Readable Layer）

**状态：PLANNED**  
**类别：Foundation / Routing & Authorization**  
**功能依赖：UI-003、UI-007**

> 本页是 BurnCloud Console UI URL 的单一 canonical source。各页面计划引用本页，不各自重新发明路径。

### TL;DR

把所有登录后 UI 收回 `/console/*` 管理 namespace：Buyer、Supplier、Admin 都是 Console workspace，而不是三个根级应用。`/console` 只表示“管理面 UI”，不授予任何权限；真正 authorization 由 Backend 决定。

### 为什么必须现在定义？

current Production Dioxus 受保护页面仍位于 `/models`、`/billing` 等 root-level paths，而 management APIs 已固定为 `/console/api/*`。Target Workbench 又使用 `/buyer/*`、`/supplier/*`、`/admin/*`。若直接照搬，会形成三套命名逻辑：旧根路径、角色根路径、`/console/api` 后端路径。

正确收敛：

```text
Public Plane        /
Data Plane          /v1/*
Management UI       /console/*
Management API      /console/api/*
Internal API        /console/internal/*
Transport           /ws
Health              /health
```

### 范围速览（In / Out）

| ✅ 做 | ❌ 不做 |
| --- | --- |
| canonical `/console` UI tree | 不让 path 授权 |
| AuthGate + WorkspaceGate route contract | 不重写 backend auth engine |
| all 25 role page paths | 不把 locale 放 URL |
| reserve `/console/api` + `/console/internal` | 不让 LiveView catch-all 吞 API |
| safe `/console` resolver | 不动态改变 legacy URL 业务含义 |
| legacy mapping policy | 不在本 Issue 删除 legacy routes |

### 审批者关注点（Reviewer Focus）

1. 是否同意所有 authenticated UI 统一进入 `/console/*`？
2. 是否同意 `/console/api`、`/console/internal` 是保留后端子树？
3. 是否同意 URL prefix 绝不构成 authorization？
4. 是否同意 legacy URL 保持原业务语义而不是按角色动态解释？

## 第二层：机器执行层（Machine Executable Specification）

### 1. Goal

建立 BurnCloud canonical route namespace 与 route-level presentation authorization contract，并为 Web/Desktop/LiveView 提供一致 deep-link 行为。

### 2. Evidence

- STATIC CONFIRMED — current `app.rs` 通过 `#[layout(AuthGate)]` 保护 root-level `/`, `/models`, `/billing`, `/providers` 等 UI routes。
- STATIC CONFIRMED — current `AuthGate` 只检查 authenticated。
- STATIC CONFIRMED — `API_PREFIX = /console/api`、`INTERNAL_PREFIX = /console/internal`。
- STATIC CONFIRMED — Server 架构明确把 management API、internal route、optional LiveView 与 data-plane fallback 组合在同一 Axum App。
- STATIC CONFIRMED — current `liveview_router()` 硬编码旧 root paths。
- STATIC CONFIRMED — Target Workbench routes 为 `/buyer/*`, `/supplier/*`, `/admin/*`，但其 RoleContext 能由 URL/前端状态切 role，因此不能作为 Production authorization source。

### 4. Authorization Contract

```text
canonical URL
    ↓
AuthGate
    ↓
WorkspaceGate (presentation)
    ↓
Page
    ↓
Management API
    ↓
Backend role/capability/tenant authorization (final authority)
```

关键规则：

```text
/console/admin/* does not grant Admin
/console/supplier/* does not grant Supplier
/console/buyer/* does not bypass tenant scope
```

WorkspaceGate 只改善 UX；Backend API 必须独立拒绝未授权读取/修改。

### 5. Legacy Route Matrix

Legacy URL 保持**原业务语义**，不能根据 active role 动态改变含义。

| Current Legacy | Migration target / policy |
| --- | --- |
| `/` | product/public decision；authenticated console entry 改用 `/console` |
| `/dashboard` | `/console` |
| `/playground` | `/console/buyer/playground`，前提 Buyer semantic parity |
| `/keys` | `/console/buyer/api-keys`，前提 owner-scope parity |
| `/customers` | `/console/admin/customers` |
| `/users` | `/console/admin/customers` |
| `/models` | `/console/admin/models`，**不得自动变 Buyer Marketplace** |
| `/settings` | `/console/admin/settings`，直到角色 settings parity 后再细分 |
| `/providers` | retain/alias `/console/admin/providers` Advanced/Legacy，待 Supply parity 后独立退役 |
| `/routes` | retain/alias `/console/admin/routes` Advanced/Legacy，待 Operations/Capacity parity 后独立退役 |
| `/guardrails` | retain/alias `/console/admin/guardrails` Advanced/Legacy |
| `/evaluation` | retain/alias `/console/admin/evaluation` Advanced/Legacy |
| `/team` | retain/alias `/console/admin/team` |
| `/logs` | retain/alias `/console/admin/logs`；**不得自动变 Buyer Logs** |
| `/billing` | 暂时 retain compatibility；Buyer Usage/Billing semantic parity 后单独决定 |

Advanced/Legacy Admin paths 是 migration compatibility，不自动进入目标主 Sidebar。

### 7. Reuse Targets / Do Not Recreate

Reuse：single Dioxus Router、AuthContext/AuthGate、LiveView Router、Axum management/internal namespaces、existing alias patterns。  
Do Not Recreate：second Router、second permission DB、locale-specific route tree、role-dependent legacy semantics。

### 8. Scope

Allowed：canonical route enum/tree、WorkspaceGate route composition、safe return_to、LiveView HTML shell routes、reserved subtree ordering/tests、legacy policy documentation。  
Avoid：具体页面业务、backend policy redesign、legacy removal、data-plane `/v1` changes。

### 9. Failure / Forbidden Fallbacks

- unauthorized workspace → explicit Forbidden/Unavailable，不 fallback Admin。
- unauthenticated → Login + safe internal return_to。
- unknown `/console/api/*` → API 404，不返回 UI HTML。
- unknown `/console/internal/*` → internal semantics，不返回 UI HTML。
- unsupported locale 不改变 route。

Forbidden：URL grants permission、locale prefix route、role-dependent `/models`/`/logs` meaning、open redirect、second Router。

### 10. Impact / Invariants

```text
public_api_cli: none
data_plane: none
frontend_routes: yes
management_api_prefix: preserved
internal_api_prefix: preserved
auth: presentation gate + backend authority preserved
```

Invariants：one Router；`/console/api`/`internal` reserved；Backend Authorization final；locale-independent URL；legacy semantics stable。

### 11. Dependencies

UI-003、UI-007。Role page plans inherit this contract；UI-005 executes legacy migration after target parity。

### 12. Stop Conditions

```text
STOP IF:
- /console UI cannot coexist safely with /console/api or /console/internal
- API/internal routes can be captured by UI catch-all
- role must be inferred from URL instead of backend
- locale must enter canonical Console URL
- legacy URL must change meaning by active role
- data-plane /v1 behavior must change
- Web/Desktop/LiveView cannot share coherent route semantics
```
