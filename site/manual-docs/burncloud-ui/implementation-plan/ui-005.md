# UI-005：迁移 Legacy Console Route Compatibility

## 第一层：人类阅读区（Human Readable Layer）

**状态：PLANNED**  
**类别：Compatibility Migration**  
**功能依赖：UI-008 + 对应目标页面 parity**

> Canonical route tree 与 legacy mapping rules 由 UI-008 定义。本页负责真正执行 compatibility migration，而不是重新定义 URL。

### TL;DR

旧 `/providers`、`/models`、`/routes`、`/logs`、`/billing` 等不能直接删除，也不能根据当前登录角色动态改变业务含义。每个 legacy URL 必须有唯一、稳定、可审计的 compatibility outcome。

### 范围速览（In / Out）

| ✅ 做 | ❌ 不做 |
| --- | --- |
| inventory legacy routes | 不直接删 route |
| redirect/alias/retain/unavailable | 不让同一 URL 随 role 变含义 |
| preserve query/deep link | 不改变 backend auth |
| Advanced/Legacy Admin compatibility | 不复制页面实现 |
| Web/LiveView/Desktop regression | 不创建第二 Router |

### 审批者关注点（Reviewer Focus）

1. 每个旧 URL 是否只有一个稳定语义？
2. `/models` 是否不会错误地变成 Buyer Marketplace？
3. `/logs` 是否不会错误地变成 Buyer tenant logs？
4. removal 是否仍是独立后续决策？

## 第二层：机器执行层（Machine Executable Specification）

### 1. Goal

把 current root-level Console deep links 安全迁移到 UI-008 定义的 `/console/*` namespace，同时保持 single Dioxus Router、backend authorization 与旧业务语义。

### 2. Evidence

- STATIC CONFIRMED — current `app.rs::Route` 包含 `/`, `/dashboard`, `/playground`, `/routes`, `/models`, `/providers`, `/keys`, `/customers`, `/users`, `/guardrails`, `/logs`, `/evaluation`, `/billing`, `/team`, `/settings`。
- STATIC CONFIRMED — current `/models` 是 operator/provider/channel availability mental model，不等同 Buyer Marketplace。
- STATIC CONFIRMED — current `/console/api/logs` 是管理日志能力，不等同 future Buyer tenant-safe Logs。
- STATIC CONFIRMED — current Billing 主要是 spend/usage analytics，不自动等价 future Buyer Balance/Top-up/Invoice page。
- STATIC CONFIRMED — LiveView 也硬编码旧根级 UI paths，所以 migration 必须同时覆盖 Dioxus Route 与 LiveView shell routes。
- UNKNOWN — `/billing` 最终 compatibility outcome 必须在 Buyer Usage/Billing parity 后 re-audit。

### 3. Entry / Starting Point

```text
crates/client/src/app.rs::Route
crates/client/src/lib.rs::liveview_router
crates/client/src/route_aliases.rs
crates/client/src/functional_layout.rs
UI-008 route matrix
completed target pages
```

### 4. Reuse Targets / Do Not Recreate

Reuse：single Router、existing aliases/Link patterns、WorkspaceGate、approved Advanced/Legacy Admin pages。  
Do Not Recreate：second Router、duplicate target pages、dynamic role-dependent URL semantics。

### 5. Scope

Allowed：legacy route inventory、redirect/alias/retain/unavailable mapping、LiveView route shell update、internal links/search/bookmark regression。  
Avoid：page business implementation、backend authorization redesign、legacy route deletion。

### 6. Behavior Contract

**Inputs**：legacy URL、authenticated identity/roles、UI-008 approved mapping、target parity state。  
**Outputs**：一个稳定 compatibility result：redirect / alias / retained legacy page / explicit unavailable。  
**Ownership**：UI-008 owns mapping truth；Router/Shell executes；backend owns authorization。  
**Side Effects**：navigation only。

### 7. Failure / Forbidden Fallbacks

- Ambiguous route 不自动映射 Admin/Buyer。
- Target 未完成时允许 retain legacy/advanced page，而不是伪装 parity。
- `/models` 不按 active role 在 Buyer Marketplace 与 Admin Models 间切换。
- `/logs` 不直接映射 Buyer Logs，除非 tenant-safe contract 与 explicit migration decision 已完成。
- `/billing` 不在语义不等价时强行映射 future Buyer Billing。

Forbidden：route deletion、role-dependent meaning、URL grants role、duplicate content copy。

### 8. Impact / Invariants

frontend navigation/deep links only；one Router；compatibility 不授予 authorization；legacy semantics stable；removal = separate Issue。

### 9. Dependencies

UI-008 + 每个 target route/page parity + implementation-time deep-link inventory。

### 10. Stop Conditions

```text
STOP IF:
- mapping would change old business meaning based on active role
- target page lacks semantic parity
- deletion is required to proceed
- second Router is proposed
- LiveView and Web/Desktop cannot share coherent outcome
- query/deep-link context cannot be preserved safely
```
