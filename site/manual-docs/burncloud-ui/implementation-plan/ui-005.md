# UI-005：迁移 Legacy Console Route Compatibility

## 第一层：人类阅读区（Human Readable Layer）

**状态：PLANNED**  
**类别：Compatibility Migration**  
**功能依赖：UI-008 + 对应目标页面 parity**

> UI-008 定义路径真相；本页只执行迁移。

### TL;DR

旧根路径不能继续承载受保护页面。迁移时把真正页面移入 `/console/*`，根级 `/models`、`/billing`、`/logs`、`/providers` 等只留下 redirect-only stub，从而保持旧 bookmark 可用，同时不留下第二套权限边界。

### 范围速览（In / Out）

| ✅ 做 | ❌ 不做 |
| --- | --- |
| inventory root legacy URLs | 不保留 root-level sensitive page |
| protected page move to `/console/*` | 不让 root redirect 读数据 |
| redirect-only compatibility | 不让 redirect 调 management action |
| preserve query/deep link safely | 不按 role 动态改 URL 语义 |
| Web/LiveView/Desktop regression | 不创建第二 Router |

### 审批者关注点（Reviewer Focus）

1. 根级旧 URL 是否只 redirect？
2. 真正敏感页面是否全部进入 `/console/*`？
3. `/billing` 是否固定去 Buyer Billing，而 Admin Billing 使用独立 canonical path？
4. Advanced/Legacy Admin 能力是否在 `/console/admin/*` 中继续存在，而不是被删除？

## 第二层：机器执行层（Machine Executable Specification）

### 1. Goal

执行 UI-008 的 route contract，把 current root-level protected UI 收敛到 `/console/*`，同时保留无业务逻辑的 root compatibility redirect。

### 2. Evidence

- STATIC CONFIRMED — current Dioxus Route 仍有 root-level `/models`、`/providers`、`/routes`、`/billing`、`/logs` 等 protected routes。
- STATIC CONFIRMED — LiveView 也硬编码这些 root paths。
- STATIC CONFIRMED — management APIs 已在 `/console/api/*`。
- STATIC CONFIRMED — current `/models` 是 operator/admin mental model，不等同 Buyer Marketplace。
- STATIC CONFIRMED — current `/console/api/logs` 是管理日志，不等同 Buyer tenant-safe Logs。
- STATIC CONFIRMED — current Billing 是用户自身 spend/usage 视角；legacy `/billing` 最接近 Buyer Billing，而新 Admin Billing 是不同业务域。

### 3. Entry / Starting Point

```text
crates/client/src/app.rs::Route
crates/client/src/lib.rs::liveview_router
crates/client/src/route_aliases.rs
crates/client/src/functional_layout.rs
UI-008
completed target pages
```

### 4. Reuse Targets / Do Not Recreate

Reuse：single Router、redirect patterns、WorkspaceGate、approved Advanced/Legacy Admin pages。

Do Not Recreate：root protected pages、second Router、duplicate target pages、dynamic role-dependent URL semantics。

### 5. Scope

Allowed：move canonical page routes under `/console/*`、root redirect stubs、LiveView route shell update、internal links/search/bookmark regression。

Avoid：backend authorization redesign、删除 legacy capability、页面业务重写。

### 6. Behavior Contract

**Inputs**：root legacy URL、UI-008 mapping、target parity。  
**Outputs**：HTTP/client redirect 到唯一 `/console/*` target。  
**Ownership**：UI-008 owns mapping truth；Router/Shell executes；backend owns authorization。  
**Side Effects**：navigation only。

根级 redirect 本身：

```text
MUST NOT render protected page
MUST NOT fetch protected data
MUST NOT call /console/api management action
MUST NOT persist business state
```

### 7. Canonical Migration Outcomes

```text
/playground  → /console/buyer/playground
/keys        → /console/buyer/api-keys
/billing     → /console/buyer/billing
/models      → /console/admin/models
/customers   → /console/admin/customers
/users       → /console/admin/customers
/settings    → /console/admin/settings
/providers   → /console/admin/providers
/routes      → /console/admin/routes
/logs        → /console/admin/logs
/guardrails  → /console/admin/guardrails
/evaluation  → /console/admin/evaluation
/team        → /console/admin/team
/dashboard   → /console
```

Admin Billing 不使用旧 `/billing`：

```text
/console/admin/billing
```

它从一开始就是新的 Admin canonical page。

### 8. Failure / Forbidden Fallbacks

- root redirect target 未完成 → migration remains BLOCKED；不能继续保留 root sensitive page 作为“临时方案”。
- unauthorized target → `/console/*` 的 AuthGate/WorkspaceGate/Backend Authorization 正常拒绝。
- `/models` 不根据 role 变 Marketplace。
- `/logs` 不根据 role 变 Buyer Logs。
- `/billing` 不根据 role 在 Buyer/Admin Billing 间切换。

### 9. Impact / Invariants

Navigation/deep links only。保持 INV-UI-ROUTE-001 / 002、one Router、Backend Authorization final、legacy semantic stability。

### 10. Dependencies

UI-008 + 对应 target page parity + implementation-time deep-link inventory。

### 11. Stop Conditions

```text
STOP IF:
- root compatibility requires sensitive page rendering
- redirect must perform protected API call
- target /console page lacks semantic parity
- mapping must vary by active role
- second Router is proposed
- Web/Desktop/LiveView cannot share outcome
```
