# UI-002：统一 Design Tokens 与 Shared Components

## 第一层：人类阅读区（Human Readable Layer）

**状态：PLANNED**  
**类别：Foundation**  
**功能依赖：无**

> 这是实施计划，不是 Codex 的直接开发授权。实现前必须针对当时 current main 重新 Evidence Audit，并创建 READY Engineering Issue。

### TL;DR

把批准后的 BurnCloud Design System 映射到现有 `visual_system.css` 和真正可复用的 Dioxus 组件上，形成唯一生产视觉语言。不是创建一套新的 `BC*` 组件库，更不是把 Tailwind/React 引入生产。

### 背景与动机（Why）

生产客户端已经有 semantic `--bc-*` tokens，但 Target Design System 对 Typography、Neutral hierarchy、Status、CTA、Spacing、Accessibility 等给出了更完整的产品语义。若逐页自己补颜色/spacing，会重新形成多套视觉系统。

### 范围速览（In / Out）

| ✅ 做 | ❌ 不做 |
| --- | --- |
| 映射 Target semantics 到 `--bc-*` | 不创建第二 token system |
| 复用/补齐真正共享组件 | 不为名字一致重复造 `BC*` wrapper |
| 固定状态/CTA/focus/accessibility | 不迁移 Role IA |
| 保持现有页面功能语义 | 不改 backend/business logic |

### 风险与安全网（Risk）

视觉迁移不能覆盖产品事实。若一个“视觉需求”需要修改页面业务状态或 backend contract，应留给页面 Issue。

### 审批者关注点（Reviewer Focus）
1. 是否继续以 `visual_system.css` 为唯一 semantic visual source？
2. 是否只在跨页面真实复用时新增共享组件？
3. 是否同意 Accessibility 高于像素级截图相似度？

## 第二层：机器执行层（Machine Executable Specification）

### 1. Goal

建立一套可被后续所有 UI 页面复用的 production token/component foundation，并保持当前单一 Dioxus frontend。

### 2. Evidence

Evidence baseline：`burncloud/burncloud@c314bff9646f9113c9a58a818552fc80c77543a6`。

- STATIC CONFIRMED — `crates/client/src/visual_system.css` 是 canonical semantic visual layer。
- STATIC CONFIRMED — 它在 `app.rs` 中作为最终 CSS layer 加载。
- STATIC CONFIRMED — `docs/ui/tokens.md` 要求新增视觉决策优先使用 `--bc-*`。
- STATIC CONFIRMED — Target Design System 要求克制的 Black/White/Gray、单一 accent、稳定状态语义、CTA hierarchy 与 accessibility。
- UNKNOWN — 哪些 target patterns 需要新增 Rust shared component；必须先审计 current components。

### 3. Entry / Starting Point

```text
crates/client/src/visual_system.css
crates/client/src/components*
crates/client/src/styles.css
crates/client/src/product_ui.css
docs/ui/tokens.md
docs/ui/system.md
```

### 4. Reuse Targets / Do Not Recreate

Reuse：`--bc-*`、现有 shared components、focus/reduced-motion/accessibility rules、现有 UI gates。

Do Not Recreate：第二 palette/token system、Tailwind runtime、重复 `BC*` API、page-local raw visual scale、online font 唯一依赖。

### 5. Scope

Allowed：visual_system/shared components/shared styles、相应 docs/checks/tests。  
Avoid：Role/Shell、页面数据 wiring、backend/API/schema、Node runtime UX。

### 6. Behavior Contract

**Inputs**：approved Design System + current Dioxus visual implementation。  
**Outputs**：统一 tokens、status/CTA/accessibility semantics 与必要 shared primitives。  
**Ownership**：visual system owns visual semantics；page owns product/data state。  
**Side Effects**：CSS/component/check changes only。

### 7. Failure / Forbidden Fallbacks

已有 pattern 必须复用；单页 pattern 不自动升级为 shared component。禁止第二 CSS framework、raw palette 扩散、牺牲 accessibility 追求截图一致。

### 8. Impact / Invariants

```text
persistence: none
external_calls: none
billing_usage_quota: none
auth_authorization: none
routing_provider: none
frontend_visual_system: yes
```

保持：one token system；one Dioxus frontend；color 不是状态唯一信号；visual layer 不定义业务真相。

### 9. Dependencies

功能依赖：无。UI-003 与所有页面迁移在需要 Target visual foundation 时依赖本计划。

### 10. Stop Conditions

```text
STOP IF:
- implementation requires a second token/component system
- target visual semantics require changing page business/backend contracts
- new shared component duplicates an existing pattern
- visual_system.css cannot remain final semantic layer
- accessibility/focus/reduced-motion cannot be preserved
```
