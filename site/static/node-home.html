What is a Node?

A small local AI control plane.

Your application talks to one stable endpoint. BurnCloud Node sits between the application and the local machine, resolving models, preparing runtimes and managing inference processes.

Node capabilities

Six responsibilities. One interface.

The first BurnCloud Node is intentionally small. It focuses on making local model execution predictable before adding network or provider complexity.

01

Local API

Expose a stable OpenAI-compatible /v1 endpoint for local applications.

02

Hardware Detect

Identify CPU, GPU, RAM and VRAM so model decisions match the machine.

03

Model Resolver

Turn a friendly model name into the right artifact and variant for available hardware.

04

Model Manager

Download, verify, cache, list and remove local model artifacts without manual file hunting.

05

Runtime Manager

Prepare and launch the local inference runtime behind the API instead of exposing runtime details.

06

Process Manager

Own model process startup, health, ports, logs, shutdown and recovery.

The direction

The endpoint stays the same even when compute moves.

BurnCloud starts with a local Node. Later, the same Node can choose private or BurnCloud Network capacity when a requested model cannot run locally—without forcing the application to change its API endpoint.
