# UI-004：统一 Node Autopilot UX 状态合同

## 第一层：人类阅读区（Human Readable Layer）

**状态：PLANNED**  
**类别：Cross-cutting / Node UX**  
**功能依赖：UI-002、UI-003、UI-007、UI-008 + BurnCloud Node 状态合同**

> UI-004 只定义“如何显示”Node/Autopilot 状态，不拥有 Resolver、Download、Runtime、Process Manager；所有使用这些状态的页面仍位于 UI-008 定义的 `/console/*` namespace 内。

### TL;DR

让 Buyer、Supplier、Admin 对同一个 Node 生命周期状态说同一种语言：Provider Serving、Resolving、Preparing、Downloading、Verifying、Starting、Local Ready、Degraded、Unsupported、Failed、Recovered。UI 只 Observe / Explain / Report，不出现人工 Download/Start/PID 控制；机器状态码保持稳定，说明文案由 UI-007 localized。

### 范围速览（In / Out）

| ✅ 做 | ❌ 不做 |
| --- | --- |
| 统一状态 vocabulary/semantics | 不实现 Node lifecycle |
| role-specific localized explanation | 不直接下载模型 |
| progress/reason/result 展示 | 不启动/停止 process |
| Unknown safe fallback | 不猜测 READY |
| machine code + localized message | 不翻译 error/model/runtime IDs |

### 审批者关注点（Reviewer Focus）
1. backend lifecycle 是否是唯一状态源？
2. `Process Spawned != Model READY` 是否被保留？
3. Recovered 是否与 Active Failed 分开？
4. locale 是否只改变 explanation，不改变 machine state/permission/route？

## 第二层：机器执行层（Machine Executable Specification）

### 1. Goal

建立跨角色共享的 Node/Autopilot state mapping 和 localized explanation 层，不复制 backend lifecycle logic，也不把 Node 状态做成路由/权限来源。

### 2. Evidence

- STATIC CONFIRMED — Target UI 明确列出统一 Node states。
- STATIC CONFIRMED — Node architecture 要求 UI 不拥有 Resolver/Preparation/Runtime/Process 生命周期。
- STATIC CONFIRMED — Production 已有 status/badge/readiness visual patterns。
- STATIC CONFIRMED — UI-007 规定 machine identifiers/error codes 不翻译；UI-008 规定 workspace route/authorization 独立于状态和 locale。
- UNKNOWN — current-main 是否已提供完整 machine-readable Node states/reason/progress/result；实施前必须重新审计。

### 3. Entry / Starting Point

```text
UI-002 shared status components
UI-003 role shell
UI-007 localization contract
UI-008 console route contract
Buyer Playground
Supplier Resources/Deployments/Reliability
Admin Capacity/Operations
BurnCloud Node runtime/demand contracts
```

### 4. Reuse Targets / Do Not Recreate

Reuse：canonical Node states + shared status pattern + shared i18n error/status mapping。  
Do Not Recreate：frontend lifecycle enum detached from backend、Process Manager、manual repair controller、per-page status dictionaries。

### 5. Scope

Allowed：state mapping、shared presentation、localized role copy、tests/checks。  
Avoid：Node backend、process/runtime actions、page business redesign、route/authorization logic。

### 6. Behavior Contract

**Inputs**：authoritative Node state/reason/progress/result + locale。  
**Outputs**：stable machine state/code + canonical UI status + localized role-appropriate explanation/action hint。  
**Ownership**：Node owns lifecycle；UI owns vocabulary/presentation/localization。  
**Side Effects**：none。

### 7. Failure / Forbidden Fallbacks

Unknown state → Unknown/safe unsupported；missing progress 不发明百分比；process alive 不等于 Ready。未知 error code 可显示 generic localized explanation + raw stable code。禁止 direct download/start/restart/process action、禁止翻译 machine state/error/model IDs、禁止根据 state 改 role/route authority。

### 8. Impact / Invariants

Read-only UX contract。保持：

```text
Process Spawned != Model READY
Recovered != Active Failed
machine code != localized explanation
Node state != authorization
locale != route
UI has no runtime authority
```

### 9. Dependencies

UI-002/UI-003/UI-007/UI-008 + authoritative Node state contracts。

### 10. Stop Conditions

```text
STOP IF:
- state must be guessed from timers/process existence
- UI must duplicate lifecycle decision logic
- status component needs direct runtime mutation
- backend cannot distinguish preparing/ready/failed/recovered meaningfully
- localization requires changing machine state/error identifiers
- state or locale must influence workspace authorization
```

- [ ] canonical states 均有唯一 mapping。

- [ ] machine state/error/model IDs 不翻译。
- [ ] explanation/status copy 由 UI-007 localized。
- [ ] Unknown 从不显示 Ready。
- [ ] missing progress 不伪造进度。
- [ ] Recovered 与 Active Problem 清楚区分。
- [ ] locale/state 不改变 UI-008 route 或 workspace authorization。
- [ ] UI 不新增 Download/Start/PID authority。
- [ ] Provider Serving → Preparing → Local Ready 与 Failed/Recovered 路径可验证。
