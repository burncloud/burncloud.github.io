**PR 说明摘要：** ## Goal Apply the Phase 2 page-by-page polish pass to Routes after Providers (#407) and Models (#408). The key correction is semantic: route resilience is now derived from active model overlap inside each routing group, not from provider count alone. Two active providers do not imply failover when they serve different model IDs. ## What changed ### Model-aware route health - derive configured model IDs for every routing group - count active upstreams per model ID - distinguish model IDs as unavailable (0 active upstreams), single-upstream (1), or redundant (2+) - derive each routing group's health from its weakest model coverage ### More truthful group states - `Unavailable`: no configured model has active coverage - `Partial coverage`: some model IDs are available while others have no active upstream - `Single upstream`: every model is available, but at least one still has only one active upstream - `Redundant`: every configured model has 2+ active upstreams ### Page-level conclusion and KPIs - add a semantic route-health conclusion above the group cards - replace provider-count availability with `Fully Available`: every configured model in the group has active coverage - define `Redundant` strictly as every configured model having 2+ active upstreams - use `Needs Attention` for single, partial, and unavailable routing groups - keep neutral metrics visually neutral and reserve…
