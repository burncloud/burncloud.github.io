**PR 说明摘要：** ## Summary Continue S0-08 with the production-side adapter behind the Traffic-owned attachment contract. ### Adds - `ExistingRouterLocalAttacher` - maps a READY local OpenAI-compatible endpoint into the existing `Channel` representation - persists through `ChannelProviderModel::create`, which also synchronizes `channel_abilities` - shares the existing `Database` through `Arc` ### Boundary Node does not create a second router, listener, or routing table. Traffic converts the ready endpoint into the routing truth BurnCloud already uses. ### Safety decision Detach is deliberately fail-closed for now. Deleting by model name would be unsafe because multiple channels may serve the same model. The next contract refinement should return/store the created channel identity and detach by that stable identity. ### Important This step establishes the production adapter but does not yet connect the Node workflow event to it. That final composition wiring should happen only after stable attachment identity is added, so `RouterAttached` cannot be claimed without evidence and cleanup remains deterministic.
