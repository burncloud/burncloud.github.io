**PR 说明摘要：** ## Sync request contract: no Provider + local preparation Defines the application-level decision used when the existing ModelRouter has or does not have a candidate for the requested model. ### Contract - Existing Provider candidate exists -&gt; serve it immediately, regardless of local preparation state. - No existing candidate + Node is actively converging (`Resolving` through `Ready`) -&gt; return `MODEL_PREPARING` immediately. - No existing candidate + Node is absent/unsupported/failed/unhealthy -&gt; normal unavailable path. - `Routable` with no existing candidate is treated as unavailable because that combination means routing truth and Node state disagree. ### Client response `MODEL_PREPARING` is HTTP 503 with a stable JSON error code and `Retry-After: 5`. The request does not wait for download, runtime preparation, process startup, or readiness. ### Boundary This PR defines the request-side contract only. It does not create a second router, does not change Existing ModelRouter truth, and does not make Traffic depend on Platform `NodeState`. ### Tests Proves: 1. Existing Provider always wins while local preparation continues in background. 2. Every active preparation state maps to `MODEL_PREPARING` when no Provider exists. 3. Unsupported/failed/absent states are not falsely reported as preparing. 4. The retryable HTTP response contract is stable.
