**PR 说明摘要：** ## S0-15 — Runtime -&gt; ProcessPlan contract Closes the framework gap where `NodeOrchestrator` invented runtime command arguments and the hard-coded readiness endpoint. ### Contract Adds a Platform-owned `RuntimeAdapter` boundary: `PreparedRuntime + PreparedArtifact -> ProcessPlan` `ProcessPlan` carries: - `ProcessSpec` - `ReadinessTarget` - `local_endpoint` The application orchestrator consumes this receipt; it no longer decides runtime-specific command lines, ports, or readiness URLs. ### Fake wiring Adds `FakeRuntimeAdapter` for the framework skeleton only. The fake owns the existing deterministic port/endpoint values. ### Recovery The orchestrator retains the successful `ProcessPlan` and reuses that exact plan during recovery instead of inventing `recovery-runtime` and a readiness URL. ### Boundary - no real llama.cpp implementation; - no real download/runtime/hardware implementation; - no second server/router/database/downloader; - runtime-specific launch knowledge belongs behind `RuntimeAdapter`; - this PR only adds the socket/contract and fake wiring.
