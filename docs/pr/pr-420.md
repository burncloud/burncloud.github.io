**PR 说明摘要：** ## Goal Stop polishing BurnCloud Console pages as isolated screens and establish one product-architecture spine that every page must follow. The current Console has individually improved pages, but cross-page logic has drifted: navigation, Overview readiness, account/credential provisioning, verification, observation, and system/governance surfaces do not consistently describe the same workflow or responsibility boundaries. This PR is intentionally the first small step of a broader coherence pass. It changes the product skeleton, not every page at once. ## Canonical flow The Console now has one responsibility flow: `Overview → Supply → Access → Verify & Observe → Govern` with pages ordered as: - Workspace: Overview - Supply: Providers → Models → Routes - Access: Customers → API Keys - Verify & Observe: Playground → Logs → Evaluation → Billing - Govern: Guardrails → Team → Settings Customers precedes API Keys because identity/account ownership should precede credential lifecycle. It is not defined as a universal environment-readiness prerequisite; an existing administrator/account may already be a valid credential owner. ## Product architecture standard Adds `docs/ui/product-flow.md` as the cross-page contract. It defines: - one primary question per page - what each page owns and must not duplicate - environment vs account vs business-account scope - the shared evidence ladder: …
