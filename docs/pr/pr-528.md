**PR 说明摘要：** ## Summary Continue Phase 0 of the BurnCloud Node skeleton by defining the first stable machine-level capability contracts. ### What this PR adds - `HardwareProfile` and accelerator DTOs - `HardwareProbe` port - `ProcessSpec`, `ProcessHandle`, and process errors - `ProcessManager` port - contract tests with fake implementations ### Boundary decisions These contracts intentionally stay inside `crates/platform/node` because they describe machine/runtime capabilities that do not require BurnCloud business semantics. This PR intentionally does **not** define: - `ModelDemand` - `ResolvedModel` - Provider or Route contracts - ModelRouter behavior - artifact/model selection rules Those belong to their owning business domains and should not be pulled into Platform merely because Node needs to consume them. ### Invariants preserved - no new listener or port - no second HTTP server - no second ModelRouter - no model/provider/router business decisions in Platform ### Why The next phase needs stable sockets before adding fake implementations and a reconciler. This PR establishes only the machine-level sockets first, so later domain contracts can be defined by their true owners.
