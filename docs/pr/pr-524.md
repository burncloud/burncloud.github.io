**PR 说明摘要：** ## Summary Add the Phase 0 BurnCloud Node runtime skeleton and attach it to the existing BurnCloud server startup path. ### What this PR does - Adds `crates/platform/node` as `burncloud-node-runtime` - Defines a minimal `NodeRuntime` and `NodeContext` - Registers the crate in the workspace - Attaches `NodeRuntime::start()` before the existing unified HTTP app is created ### Architecture invariants This skeleton intentionally does **not**: - bind another network port - create a second HTTP server - create a second ModelRouter - own Model / Provider / Route / Billing business decisions The existing BurnCloud unified gateway remains the only server entry point and continues to own the configured host/port (including the current default `127.0.0.1:3000`). ### Why This creates the first stable slot for Node capabilities so hardware/runtime/process pieces can be added later without inventing a parallel server or routing stack.
