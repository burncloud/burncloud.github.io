**PR 说明摘要：** ## Clarify Existing ModelRouter ownership Follow-up to #557 after clarifying that Existing ModelRouter candidates include both external Provider channels and READY/Routable local Node channels. ### Changes - Rename `UseExistingProvider` to `UseExistingRoute`. - Document that an existing candidate may be external or local. - Explicitly prohibit Node request logic from choosing local-vs-external preference. - Add `Routable` coverage: with an existing candidate, use the existing route; without a candidate, treat it as routing-truth inconsistency/unavailable rather than `MODEL_PREPARING`. ### Boundary This PR intentionally does **not** implement `LocalFirst` in Node. Candidate preference belongs to Traffic/Scheduler. A later Traffic-owned policy can add LocalFirst/CostFirst/etc. without changing Node orchestration.
