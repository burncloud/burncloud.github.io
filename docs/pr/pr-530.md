**PR 说明摘要：** ## Summary S0-04 of the Node skeleton: define the minimal runtime convergence state machine that the future reconciler must follow. ### State path `Absent -> Resolving -> PreparingArtifact -> ArtifactReady -> PreparingRuntime -> Starting -> Ready -> Routable` Failure/health paths are also represented with `Failed` and `Unhealthy`. ### Adds - `NodeState` - `NodeStateMachine` - explicit allowed transitions - `InvalidNodeTransition` - serving/failure predicates - tests that forbid skipping directly to `Ready` or `Routable` - retry and unhealthy-path tests ### Important boundary The state model describes runtime convergence only. It does not decide which BurnCloud Model, Provider, or Route should be selected. Those decisions remain with their owning business domains. ### Why The next `DemandReconciler` needs a fixed rail to move along. Explicit transitions also prevent future implementations from claiming `READY` or `ROUTABLE` without passing the intermediate evidence-producing stages. ### Preserved invariants - no new listener or port - no second HTTP server - no second ModelRouter - no real GPU/process/model implementation yet
