**PR 说明摘要：** ## Goal Create a fast, repeatable runtime visual truth path for the current Dioxus console so ChatGPT/Codex can review real rendered pages and click paths instead of inferring UI quality from RSX/CSS and compile success. **This PR no longer uses GitHub Actions for staging/browser acceptance.** The primary loop runs directly on the developer/Codex machine to avoid CI queue, install and rebuild latency. ## Local staging topology `local BurnCloud binary → isolated SQLite → BurnCloud server/management APIs/router → Dioxus LiveView → agent-browser → screenshots + machine-readable audit report` The runner explicitly sets `BURNCLOUD_DATABASE_URL` to a dedicated temporary staging database under `target/staging-runtime/`. It does not use `BURNCLOUD_FRESH_DB` against the normal default DB, so developer data is protected. ## One-command entrypoint The runner: - reuses `target/debug/burncloud` when source has not changed; - performs only an incremental `cargo build --bin burncloud` when needed; - creates an isolated SQLite DB; - starts BurnCloud and waits for `/health`; - runs the real browser journey; - writes screenshots/reports to `target/staging-audit/`; - stops the server and removes the temporary DB by default.
