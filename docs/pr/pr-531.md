**PR 说明摘要：** ## Summary S0-05: add the minimal DemandReconciler skeleton that drives Node convergence one evidence-backed step at a time. ### Adds - `DemandReconciler` - `ReconcileAction` - `ReconcileEvidence` - golden-path reconciler tests - wrong-evidence/skip prevention tests - Node runtime skeleton README ### Important correction to S0-04 The reconciler exposed an important invariant: spawning a process is not proof that it is READY. This PR therefore inserts `WaitingReady` between `Starting` and `Ready`: `Starting -> WaitingReady -> Ready` `ProcessStarted` only reaches `WaitingReady`. Only explicit `ReadinessVerified` evidence reaches `Ready`. Fixed sleeps are explicitly not readiness evidence. ### Full rail `Absent -> Resolving -> PreparingArtifact -> ArtifactReady -> PreparingRuntime -> Starting -> WaitingReady -> Ready -> Routable` ### Boundary The reconciler decides which stage is next; it does not implement model resolution, artifact selection, Provider selection, routing policy, GPU detection, or process execution. `Routable` means attachment to the existing BurnCloud ModelRouter path, never creation of a second router/server/listener. ### Next S0-06 should build the composition root that wires the reconciler to fake stage owners without introducing real business implementations.
