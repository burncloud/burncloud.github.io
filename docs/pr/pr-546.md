**PR 说明摘要：** ## S0-12 — Action -&gt; owner contract -&gt; evidence Turns the application skeleton from a manually pushed state rail into an orchestrated preparation rail. A single `ModelDemand` can now drive: `Resolve -> PrepareArtifact -> PrepareRuntime -> StartProcess -> VerifyReadiness -> Ready` For every step the orchestrator follows the same invariant: `ReconcileAction -> call owner port -> successful result -> ReconcileEvidence` Success evidence is never emitted before the capability call succeeds. ### Boundaries - Supply still owns model resolution. - Platform still owns hardware/artifact/runtime/process/readiness/health ports. - The orchestrator only wires calls and carries temporary receipts between them. - It deliberately stops at `Ready` before `AttachToExistingRouter`. - Traffic attachment, detach, unhealthy and recovery are S0-13. - No real capability implementation and no second server/router/downloader/database. ### Framework note The readiness endpoint is still a skeleton placeholder carried as a temporary receipt. A later Process/Runtime contract should return the real endpoint; application orchestration must not permanently invent ports.
