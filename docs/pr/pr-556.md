**PR 说明摘要：** ## Node READY -&gt; existing router composition Closes the framework gap where callers had to manually coordinate local preparation and route attachment as two unrelated steps. ### Application rail `ModelDemand -> prepare_until_ready -> ProcessPlan.local_endpoint -> Traffic attachment side effect -> RouterAttached evidence -> Routable` Adds `prepare_and_attach_node_route`, which: - runs the existing local preparation rail; - stops cleanly when local execution is unsupported; - takes the local endpoint only from the successful runtime-owned `ProcessPlan`; - invokes the caller-supplied Traffic attachment side effect only after READY; - records `RouterAttached` only after that side effect succeeds; - returns the stable attachment receipt; - leaves the reconciler at READY if attachment fails. ### Boundary The helper does not create a second server, router, routing table, database, or endpoint. The actual Traffic adapter remains the owner of writing existing routing truth. This PR only composes the already-defined application seam. ### Test Adds a fake acceptance test proving a supported demand reaches `Routable` through one application call and that the attachment receives the model plus the endpoint produced by `RuntimeAdapter`.
