**PR 说明摘要：** ## S0-14 — Framework Fake E2E Adds an application-level acceptance test for the framework skeleton. The test supplies a `ModelDemand` and fake boundary side effects, then proves the framework owns the success rail: `ModelDemand -> Resolve -> Artifact -> Runtime -> Process -> Readiness -> Ready -> Attach -> Routable -> Unhealthy -> Detach -> Recover -> Ready -> Reattach -> Routable` It does not manually emit successful stage evidence for the preparation or recovery steps. Evidence is produced by the framework only after the relevant fake owner port succeeds. Also adds `NodeOrchestrator::recover_until_ready()` so recovery Process/Readiness/Health calls are framework-owned rather than test-owned. ### Important skeleton limitation The recovery ProcessSpec and readiness endpoint are still placeholders. This PR intentionally exposes that remaining contract gap instead of implementing real runtime behavior: Process/Runtime contracts must eventually return enough launch/readiness information so the orchestrator never invents program names or ports. ### Boundary - no real NVIDIA/runtime/download/health implementation; - no second server/router/database/downloader; - cross-domain acceptance lives under the application/server layer, not platform; - Traffic attach/detach remains supplied through the application seam.
